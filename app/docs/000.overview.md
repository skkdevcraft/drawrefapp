# Project Overview

## Purpose

This project is a lightweight web application designed to help people learn to draw from three-dimensional references.

The application displays a 3D model that can be inspected from different viewpoints while the user draws it. The primary goal is to provide a simple, shareable, and responsive reference viewer rather than a full 3D editor.

The viewer should feel fast, predictable, and distraction-free.

---

## Design Philosophy

### Simplicity First

The application should remain understandable by a single developer.

Prefer:

* Small modules
* Clear responsibilities
* Minimal dependencies
* Explicit behavior

Avoid unnecessary abstraction and complexity.

---

### URL-Driven State

A core feature of the application is shareability.

A URL should reconstruct the scene as closely as possible, including:

* Loaded model
* Camera position
* Camera target
* User settings

The URL acts as the canonical representation of the current scene state.

---

### Progressive Growth

The initial feature set is intentionally small.

New capabilities should be added gradually through:

* Additional settings
* Additional scene controls
* Additional viewing aids

The architecture should support growth without requiring major rewrites.

---

### Mobile-Friendly by Default

The application is expected to be used on phones, tablets, and desktop devices.

User interfaces should:

* Support touch interaction
* Provide large touch targets
* Avoid precision-dependent controls

Desktop support is important, but mobile usability should not be treated as an afterthought.

---

## Architectural Pillars

### Settings Registry

All configurable settings are defined in a centralized settings registry.

The registry is responsible for:

* Defaults
* Validation
* UI generation
* URL serialization
* URL deserialization

New settings should be added by registering them rather than writing custom handling throughout the application.

See:

* `docs/002.settings.md`

---

### Event-Driven Rendering

Rendering should occur only when necessary.

The application is not intended to run a permanent animation loop.

Rendering should happen when:

* The camera changes
* The model changes
* A setting changes
* The viewport changes

When the scene is idle, rendering should stop completely.

This is a fundamental performance requirement.

---

### Model Normalization

Models may come from different sources and use different scales.

Before display, models should be normalized so that:

* They are centered at the origin
* They appear at a consistent visual size
* Camera fitting behaves predictably

The user should not need to think about model scale.

---

## Technology Choices

Current stack:

* Vite
* TypeScript
* Three.js
* Native DOM APIs
* CSS Custom Properties

The project intentionally avoids frontend frameworks.

UI components are created using standard browser APIs and styled through CSS.

---

## Non-Goals

The project is not intended to become:

* A 3D modeling tool
* A CAD application
* A game engine
* A scene editor

Features should be evaluated against the primary goal of providing effective drawing references.

## Decision Rule

When making implementation decisions:

1. Preserve shareable URLs.
2. Preserve event-driven rendering.
3. Keep the viewer responsive on mobile devices.
4. Prefer simpler solutions over more abstract solutions.
5. Favor maintainability over cleverness.

If a proposed change conflicts with these principles, revisit the design before implementing it.

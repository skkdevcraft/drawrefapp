I want to create a web site that help a person to learn to draw. It will show a 3D model and will allow the user to rotate it to see it in different angles while drawing it.

The app will allow the user to tweak some scene settings. As first step we will introduce the UI interface (a trigger button and a settigns panel) with a modular user interface for adding more settings. All settings values are stored in the URL query string, so sharing the url will rebuild the scene precisely. We will start with minimum settings and add more gradually.

---

## 1. Model Loading
- The model is a static asset served from the same origin.
- The user provides a model **name** (or relative path) – e.g. `bust.glb`, `hand.gltf`.
- The app resolves the name to a URL: `./models/{name}` (the file extension determines the loader).
- **Supported formats** (via dynamic imports of Three.js loaders):
  glTF/GLB, OBJ, FBX, STL, PLY, 3MF, Collada (DAE), etc.  
- **Fallback**: A default model (simple cube) is embedded so the viewer never starts empty.

After loading:

1. Compute world-space bounding box.
2. Translate model so bounding box center becomes (0,0,0).
3. Compute bounding sphere.
4. Uniformly scale model so sphere radius equals target radius.

All loaded models are normalized before camera fitting.

---

## 2. Scene Setup & Camera
- **Centered model**: The model is automatically positioned at origin and scaled so that its bounding sphere fills **80%** of the smallest canvas dimension (with a small margin).
- **Camera**: PerspectiveCamera, distance computed automatically from the bounding sphere.
- **Target**: Always the center (0, 0, 0)
- **OrbitControls** (from `three/examples/jsm/controls/OrbitControls`):
  - Rotate: one‑finger drag / mouse drag.
  - Zoom: pinch gesture / scroll wheel.
  - Target locked to 0, 0, 0; no free‑look.
  - Damping (inertia) enabled.
---

## 6. UI Panel
- **Trigger button**: A floating circular button, initially **top‑left** corner.
- Button position is **configurable** via a small setting in the panel: top‑left, top‑right, bottom‑left, bottom‑right.
- **Tap the button** → a panel slides in from the same edge allowing both the settings and the scene to be visible.
- All controls are plain HTML elements (no framework), styled with CSS for fat touch targets (minimum 44×44 px).
- The model scene is visible While the UI panel is visible so the user see the changes on the model.
- Elegant, slik, cool, modern user interface.

---

## 7. Performance (Idle Rendering)

Rendering is event-driven.

The renderer runs only while:
- camera is moving
- controls are damping
- scene state changes

When the scene becomes idle, the animation loop stops completely.

---

## Settings Architecture

Each setting is defined by:

- id (URL key)
- label
- type (boolean, number, select, color, action)
- default value
- serializer/deserializer

The UI panel is generated from a settings registry.

Adding a new setting should require:
1. Adding the setting definition.
2. Applying its value to the scene.

No manual URL handling per setting.

---

## Scene State Version

A query parameter `v` identifies the state schema version.

Example:

?v=1&model=skull.obj&camera=...

Future URL formats may evolve while preserving backward compatibility.

---

## 8. State Encoding & Sharing
- **All configurable settings** are serialised into a the query string `?model=<model name>&setting1=<value1>&...`.
- Parameters included:
  - `model` (string)
  - `camera` (spherical coords: theta (degrees), phi (degrees), radius) - target is always 0,0,0.
- **On load**: parse query string, decode, and immediately apply all settings (model load, camera jump).  
- **On change**: debounced (300ms) `history.pushState` to update the URL without reload.

The URL is the single source of truth for shareable state.

All configurable settings must:
- have URL serialization
- have URL deserialization
- define a default value

Missing parameters imply defaults.

---

## 9. Screenshots & Reset Views
- **Capture Screenshot** exports the current canvas content as a PNG with a preset filename (`study-{date}.png`). Screenshot captures only the WebGL canvas. UI elements are excluded.
- **View presets**:
  - Front: camera at (0°, 0°), radius same.
  - Side: (90°, 0°)
  - Three‑Quarter: (45°, 30°)
  - Top: (0°, 90°)
  - Reset Default: the computed initial “fit” view.

## 10. Technical Implementation Notes
- **Stack**: Vite + vanilla TypeScript, Three.js (and types).
- **Files**: `index.html`, `style.css`, `main.ts`.
- **Loaders**: Use loaders and other addons like this:
```ts
import * as THREE from 'three'
import * as Addons from 'three/examples/jsm/Addons.js';

const loader = new Addons.GLTFLoader();
```
- **OrbitControls** imported from `three/examples/jsm/controls/OrbitControls`.
```ts
import * as Addons from 'three/examples/jsm/Addons.js';
//...
const controls = new Addons.OrbitControls(camera, canvas);
//...
```
- All UI elements are built with `document.createElement`; styles are in `style.css` using CSS custom properties for theming.
- **Touch friendly**: inputs are large, the panel can be closed with a swipe or tap outside.

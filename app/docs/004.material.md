# Material Preset Setting Type

## Purpose

The `material-preset` setting provides artist-friendly control over the appearance of the study model.

The goal is not physical material authoring. The goal is to quickly change how forms, values, highlights, and shadows read during drawing practice.

Users should select a material based on its visual appearance rather than by adjusting low-level rendering parameters such as roughness or metalness.

---

# Setting Definition

A material preset is represented by a string value.

```ts
type MaterialPreset =
  | 'plaster'
  | 'clay'
  | 'bronze'
  | 'matte-black'
  | 'chrome';
```

Example:

```ts
{
  id: 'material',
  label: 'Material',
  type: 'material-preset',

  defaultValue: 'plaster',
}
```

---

# Serialization

The setting is serialized as a standard query parameter.

Example:

```text
?material=plaster
```

Possible values:

```text
plaster
clay
bronze
matte-black
chrome
```

Invalid values must fall back to the default.

Example:

```text
?material=banana
```

becomes:

```text
plaster
```

---

# Preset Definitions

The implementation is free to tune the exact material values.

The following descriptions define the intended visual appearance.

---

## Plaster

Default study material.

Characteristics:

* Light neutral color
* Matte appearance
* Minimal reflections
* Excellent readability of form and shadow masses

Suggested implementation:

```ts
{
  color: '#d8d6d0',
  roughness: 0.95,
  metalness: 0.0,
}
```

Use case:

* General drawing practice
* Academic studies
* Figure studies

---

## Clay

Traditional sculptural appearance.

Characteristics:

* Warm clay color
* Matte surface
* Slightly darker than plaster
* Enhanced form readability

Suggested implementation:

```ts
{
  color: '#9d7f68',
  roughness: 0.95,
  metalness: 0.0,
}
```

Use case:

* Anatomy studies
* Sculptural form studies
* Gesture and mass studies

---

## Bronze

Traditional cast sculpture appearance.

Characteristics:

* Metallic surface
* Visible highlights
* Rich value variation

Suggested implementation:

```ts
{
  color: '#8b5a2b',
  roughness: 0.35,
  metalness: 1.0,
}
```

Use case:

* Classical sculpture references
* Highlight studies
* Reflective form studies

---

## Matte Black

High-contrast silhouette material.

Characteristics:

* Dark surface
* Minimal reflections
* Strong shape readability

Suggested implementation:

```ts
{
  color: '#111111',
  roughness: 1.0,
  metalness: 0.0,
}
```

Use case:

* Silhouette studies
* Shape design
* Value grouping exercises

---

## Chrome

Highly reflective material.

Characteristics:

* Mirror-like reflections
* Strong highlight behavior
* Emphasizes surface curvature

Suggested implementation:

```ts
{
  color: '#ffffff',
  roughness: 0.0,
  metalness: 1.0,
}
```

Use case:

* Reflection studies
* Highlight studies
* Advanced rendering observation

---

# User Interface

## Overview

The setting should not be presented as:

* Dropdown menu
* Radio buttons
* Text-only list

Instead, each material preset should be represented by a visual preview generated from the actual model.

Users should choose based on appearance rather than names.

---

# Preset Preview Cards

The control consists of a horizontal or wrapped collection of preview cards.

Example:

```text
┌─────────┐ ┌─────────┐ ┌─────────┐
│ Preview │ │ Preview │ │ Preview │
│ Plaster │ │  Clay   │ │ Bronze  │
└─────────┘ └─────────┘ └─────────┘

┌─────────┐ ┌─────────┐
│ Preview │ │ Preview │
│  Matte  │ │ Chrome  │
└─────────┘ └─────────┘
```

The exact layout is implementation-defined.

The currently selected preset should be visually highlighted.

---

# Preview Generation

## Principle

Previews must be generated from the actual loaded model rather than from static image assets.

This ensures previews accurately represent:

* Current model geometry
* Current lighting conditions
* Current rendering style

---

## Rendering Procedure

For each material preset:

1. Clone or temporarily reuse the current model.
2. Apply the preset material.
3. Position the model using a fixed preview camera.
4. Render into an off-screen render target.
5. Convert the rendered image into a thumbnail.
6. Display the thumbnail within the preset button.

The thumbnail becomes the visual representation of the preset.

---

## Preview Camera

The preview camera should be fixed.

Suggested view:

```text
Three-Quarter View
Azimuth: 45°
Elevation: 30°
```

This view generally provides good visibility of:

* Silhouette
* Form
* Highlights
* Shadow masses

---

## Preview Lighting

The preview renderer should use a fixed lighting setup.

The preview should not change when the user edits the scene lighting.

Reason:

The goal is to compare materials consistently.

Example preview lighting:

```text
Azimuth: 45°
Elevation: 45°
Intensity: 1.5
Softness: 0.5
```

---

## Thumbnail Refresh

Preview thumbnails should be regenerated when:

* A new model is loaded
* The material preset definitions change

Preview thumbnails should not be regenerated when:

* Camera moves
* User rotates the model
* User changes scene lighting

This prevents unnecessary rendering work.

---

# Interaction

Selecting a preview card must:

1. Update the material preset value.
2. Apply the preset to the displayed model.
3. Trigger a render request.
4. Update the URL through the standard settings serialization system.

The change should be immediate.

---

# Performance

Preview generation should occur asynchronously.

Requirements:

* Main viewer remains responsive.
* Thumbnail generation must not block interaction.
* Previews may appear progressively.

Implementations may:

* Generate previews lazily.
* Queue preview renders.
* Cache generated thumbnails.

---

# Caching

Implementations should cache generated preview images.

Recommended cache key:

```ts
{
  model: modelName,
  preset: presetName,
}
```

Cached previews may be reused until:

* The model changes
* The preset definition changes

---

# Future Compatibility

Additional presets may be introduced without changing the control type.

Examples:

```ts
'marble'
'wood'
'terracotta'
'silver'
'gold'
'toon'
```

The UI implementation should automatically render previews for any registered material preset.


These presets should provide a broad range of appearances useful for artistic observation and drawing studies.

# Light Setting Type

## Purpose

The `light` setting type provides a compact and intuitive way to control directional scene lighting.

The control is designed for artists rather than technical users. Users should think about:

* Where the light comes from
* How strong it is
* How soft it is

The UI should never expose technical concepts such as Cartesian coordinates, shadow map sizes, or renderer-specific parameters.

The control must be touch-friendly and usable on both desktop and mobile devices.

---

# Setting Definition

A light is represented by:

```ts
type LightValue = {
  azimuth: number;
  elevation: number;
  intensity: number;
  softness: number;
};
```

Meaning:

| Property  | Description                                           |
| --------- | ----------------------------------------------------- |
| azimuth   | Horizontal direction around the model in degrees      |
| elevation | Vertical direction in degrees                         |
| intensity | Light intensity multiplier                            |
| softness  | Controls shadow edge softness and apparent light size |

Example:

```ts
{
  id: 'keylight',
  label: 'Key Light',
  type: 'light',

  defaultValue: {
    azimuth: 45,
    elevation: 30,
    intensity: 1.0,
    softness: 0.5,
  },
}
```

---

# Light Semantics

The light is treated as a directional light source aimed toward the scene origin.

The user controls:

* Horizontal direction (azimuth)
* Vertical direction (elevation)
* Brightness (intensity)
* Softness

The implementation may internally convert these values into whatever representation is required by Three.js.

The UI should never expose Cartesian coordinates.

---

# Serialization

The light setting is serialized into a single query parameter.

Example:

```text
?keylight=45,30,1,0.5
```

Format:

```text
azimuth,elevation,intensity,softness
```

Example:

```text
?keylight=120,60,1.5,0.8
```

Deserialization must:

* Validate all values
* Clamp values to valid ranges
* Fall back to defaults when invalid

---

# Light Control UI

## Overview

The light control is a custom interactive widget.

It should feel similar to positioning a studio light around a sculpture.

The control consists of:

1. Azimuth Arc
2. Elevation Arc
3. Softness Arc
4. Intensity Ring

All interactions must support:

* Mouse
* Touch
* Pointer Events

Minimum touch target size:

```text
44 × 44 px
```

The control should be usable without entering numerical values.

---

# Layout

```text
             Elevation Arc

                  ▲
             ╭────────╮
          ╭──╯        ╰──╮

       ◄──── Light Sphere ────►

          ╰──╮        ╭──╯
             ╰────────╯

             Softness Arc

             Intensity Ring
```

The exact visual appearance is implementation-defined.

The widget should present itself as a simplified light gizmo rather than a form.

---

# Azimuth Control

## Purpose

Controls horizontal light direction.

## Interaction

The user drags a handle around a circular arc.

Example:

```text
Top View

          0°

    315°      45°

270°    ●     90°

    225°    135°

         180°
```

## Range

```text
0° → 360°
```

## Behavior

Dragging updates:

```ts
light.azimuth
```

continuously.

---

# Elevation Control

## Purpose

Controls light height.

## Interaction

The user drags a handle along a vertical arc.

Example:

```text
90°  (directly above)

│
│
│
30°
│
│
0°   (horizon)
```

## Range

```text
0° → 90°
```

## Behavior

Dragging updates:

```ts
light.elevation
```

continuously.

---

# Intensity Control

## Purpose

Controls light strength.

## Interaction

The user drags a handle around an outer intensity ring.

The interaction should feel similar to rotating a dial.

The exact visual implementation is not prescribed.

## Range

```text
0.0 → 5.0
```

## Default

```text
1.0
```

## Behavior

Dragging updates:

```ts
light.intensity
```

continuously.

---

# Softness Control

## Purpose

Controls how hard or soft the light appears.

For drawing studies this influences:

* Shadow edge sharpness
* Terminator softness
* Form readability
* Contrast between light and shadow masses

Artists often study the same model under both hard and soft lighting conditions.

## Interaction

The user drags a handle along a dedicated softness arc integrated into the widget.

The control should communicate a transition from:

```text
Hard Light ←────→ Soft Light
```

rather than emphasizing numerical values.

## Range

```text
0.0 → 1.0
```

Meaning:

| Value | Meaning         |
| ----- | --------------- |
| 0.0   | Very hard light |
| 0.25  | Hard light      |
| 0.5   | Medium softness |
| 0.75  | Soft light      |
| 1.0   | Very soft light |

## Default

```text
0.5
```

## Behavior

Dragging updates:

```ts
light.softness
```

continuously.

---

# Visual Feedback

The widget should provide immediate visual feedback.

Examples:

* A small sun icon representing the light source
* Direction indicators
* Highlighted arcs
* Animated handle movement

For softness, the widget may additionally display:

* Hard-light icon ↔ soft-light icon
* Sharp shadow preview ↔ blurred shadow preview
* Terminator preview
* Gradient preview

The user should always understand:

* Where the light is located
* How high it is
* How strong it is
* How soft it is

without reading documentation.

---

# Optional Numeric Display

The UI may display current values as read-only labels.

Example:

```text
Azimuth: 45°
Elevation: 30°
Intensity: 1.0
Softness: 0.5
```

These values are informational only.

Direct numeric editing is not required.

---

# Scene Updates

Changes to the light control must:

1. Update the light value.
2. Apply the change immediately to the scene.
3. Trigger a render request.
4. Update the URL through the standard settings serialization system.

Updates should feel real-time while dragging.

---

# Initial Lights

The first light introduced by the application is:

```ts
{
  id: 'keylight',
  label: 'Key Light',
  type: 'light',

  defaultValue: {
    azimuth: 45,
    elevation: 30,
    intensity: 1.0,
    softness: 0.5,
  },
}
```

Additional lights may be added later using the same setting type.

Examples:

```ts
{
  id: 'filllight',
  label: 'Fill Light',
  type: 'light',
}

{
  id: 'rimlight',
  label: 'Rim Light',
  type: 'light',
}
```

The UI implementation should therefore be generic and reusable for any setting of type `light`.

---

# Future Compatibility

The `light` setting type is expected to evolve.

Potential future additions:

```ts
type LightValue = {
  azimuth: number;
  elevation: number;
  intensity: number;
  softness: number;

  color?: string;
  temperature?: number;
};
```

Future additions should remain backward compatible with existing serialized URLs whenever practical.
